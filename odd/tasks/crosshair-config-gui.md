# Native crosshair configuration GUI

## Objective and rationale
Provide a usable Minecraft-native pixel-art configuration screen for the named crosshair manager. User selected four generated types (Cross, Dot, X, Circle), live edits and persistent settings across restarts. Disable custom crosshair restores vanilla.

## Scope and product decisions
- Settings: selected type, enabled, inversion, size, thickness, gap, RGB color and opacity. Defaults match current opaque-white GUI_INVERT cross (17 pixels, center once).
- Four deterministic generated geometries; no overlapping fills, including thick/diagonal/circular cases, to avoid repeated inversion.
- Keep original named manager API and default object; register/select a dedicated configured object for live edits.
- Native Screen nearly fills the GUI viewport, flat pixel-font text without shadows.
- Background #001C05, panels/tabs #001006, warm white/light gray text, selected tab pale-cyan thin bottom line. User follow-up now explicitly requests visible button/checkbox text, superseding the original unnamed-tab restriction: show navigation labels, preset actions and On/Off beside checkbox squares. Preserve pixel styling/column alignment.
- Left stacked rectangular panels, consistent row heights, wide empty right zone. Labels left, values right as plain text. No sliders, surrounding numeric boxes, gradients, rounded corners, modern shadows or showy animation.
- Common right-column square checkboxes: thick #FF8F8F enabled border, darker interior; white disabled border, black interior. Never green boolean state.
- Plain-value controls: click/keyboard editing or stepping with valid input handling and native focus/narration. Numeric ranges bounded. Escape returns to previous screen. Resizing/small GUI viewports must keep controls reachable (scroll if needed).
- Remappable native key opener, unbound by default to avoid game conflicts; documented via Controls. User now also requests client-only /crosshaireditor to open the same configuration screen, sharing the settings owner and deferred tick opener. No web UI, server permissions or added dependencies.
- JSON config under Fabric config directory, explicit defaults/validation and graceful invalid-file/IO handling; do not silently destroy invalid config or claim a failed save succeeded. File writes bounded to user-authorized config.

- Defaults preserve 17 unique pixels and do not double-invert center; all preset fills disjoint at supported settings.
- Changing controls updates selected configured object; save/reload round-trips; malformed/unsupported input does not crash game or silently overwrite original invalid files.
- Controls mouse/keyboard operable and understandable; visible button/tab text and checkbox On/Off states match narration. Selected preset has explicit status; other preset rows show selection action. Focus visible without web-style effects. Values/checkbox column alignment across blocks and resizing.
- Follow-up regression tests must assert actual rendered crosshair geometry/pipeline/color after labelled control actions, and persisted state, not only changed settings. Disabled=vanilla remains covered by actual HUD wiring tests.
- Native open/close and enabled/disabled behavior preserved; one config state owns live changes, no manager redesign.
- Client /crosshaireditor is registered on each supplied client dispatcher, no OP/server request. Executing queues opening; simulated chat closes first, next tick opens exactly one existing config screen with shared settings and no chat screen as return target. Coalesce duplicate/key requests and discard stale requests on unavailable world/other menu. Works when custom crosshair disabled.
